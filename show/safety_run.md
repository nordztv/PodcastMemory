# Safety-net run

Followed by the scheduled task at about 5:50am Sydney time every weekday (Scott's choice, 13 Nov 2026). The 3am morning run should already have delivered this morning's call. This run only acts if it didn't. Work unattended; never ask questions.

Let `DATE` = **today's** Sydney date, `EP` = `REPO/archive/YYYY/MM/DATE`.

1. If `EP/delivered_am.txt` or `EP/delivered.txt` exists (even one that says "script only, not voiced": Scott was already told this morning): everything is fine. Stop. No message, no notification, no commit.
2. If the morning call was written (`EP/script/am_*` files, and `EP/notes.md` lists them all) but nothing was delivered: the audio failed. Run `sh engine/setup.sh`, then `sh engine/build_episode.sh DATE am`, send `~/podcast/out/Mizuki_DATE_morning_call.mp3` with SendUserFile (status "proactive", display "attach"), create `EP/delivered_am.txt`, commit and push. If the voice engine is blocked, follow `show/daily_run.md` step 6b (send the readable script and say so).
3. If there is no morning call, or only part of one: the 3am run didn't finish. Keep any files that are complete and write the rest. Follow `show/daily_run.md` from the start, with these limits so it's out **by about 7:15am**: a shorter morning call (about 20 to 25 minutes: how she is, the biggest news if any, and what's on her mind; she overslept), research limited to twenty minutes, and the memory updates done after delivery. On a Monday, skip step 2b while writing; after delivering, do `show/daily_run.md` step 2b (her week's journal, money, arcs and audit) only if `memory/mizuki_life.md` has no "Week ending SUNDAY_DATE" entry yet (the 3am run may have done it before failing), and say so in the message. Her shorter call will print a length CHECK: that's expected. At 7:15am deliver whatever is built.
4. In cases 2 and 3, tell Scott in one short SendUserMessage that the 3am run didn't deliver and what this run did, and send a push notification saying the morning call is ready (or that it couldn't be recorded).
